## V9 — SurroSelect smoke-test bug (before any registered Stage-6 run) — 2026-11-02
During a smoke test of the tool on the new problem `lshape_L1` (seed 0, N = 64 and 256) and a quick check of the KRR and polynomial members on `heatcomp_L2` and `convdiff_L1` (N = 64, 256), the wide-range kernel-ridge member returned a test error of 0.5 (10x worse than any other member). Cause: the closed-form leave-one-out residual divides by 1 - H_ii, which was clipped at 1e-6 (and computed by cancellation), producing spuriously tiny LOO scores for near-interpolating fits; the length-scale grid was also defined for inputs on [0,1] but with the [-1,1] limits of the benchmark's wide-range control. Fix (committed before any registered run): 1 - H_ii computed without cancellation (KRR: sum_j Q_ij^2 lam N/(w_j + lam N); polynomial: (1 - sum U_ij^2) + sum U_ij^2 lam N/(s_j^2 + lam N)), no clipping above 1e-12, ridge values with condition number above 1e12 skipped, length-scale grid [0.05, 15]·sqrt(p) on [0,1]-scaled inputs (= [0.1, 30]·sqrt(p) on [-1,1]); a regression test was added. The smoke tests showed test errors of all pool members on lshape_L1 (seed 0, N = 64, 256) and of the KRR and polynomial members on three problems; the pool, criteria, tie band, folds and all pre-registered thresholds were NOT changed after seeing them. Addendum v3.0 stated that no surrogate error on the new problems had been seen; this entry corrects that statement.

## V10 — SurroSelect pickling bug found by the plain-file validation (2026-11-04)
After the `metric` option was added (v3.1), a fitted selector stored a lambda and could no longer be saved by `surroselect fit --model`; the command-line unit test had been run before the change and the full tool test suite was not re-run. The plain-file validation (experiment E8) exposed the failure ("Can't get local object"). Fix: the metric function is a property computed from the metric name. The registered evaluation (experiments C, S, R) uses the library interface without pickling and is unaffected; all tool tests were re-run after the fix.

## V11 — Retrospective run promised in addendum v3.0 section 6.4 was reported late (2026-11-05)
Review round 1 noted that the descriptive run of the tool on the 36 earlier problems (N = 256, seed 0), promised in addendum v3.0 section 6.4, had not been delivered. It was made on 2026-11-05 (`code/experiments/exp_retro.py`, `analyze_retro.py`) and is reported in Supplement section S-retro; it is design-informed and not evidence for criteria S1-B2. No pool, grid or criterion was changed.

## V12 — Tuned-network search space narrowed in the addendum text after the criteria commit (2026-11-02)
Commit 781e318, ten minutes after a99c2c6, changed the addendum's description of the tuned network from depth 2-5, width 64-512 to depth 2-4, width 64-256 and added the 6,000-epoch final training, for compute reasons, before any evaluation run (chain script 08:51). This is disclosed here and in the paper's limitations; it weakens the tuned network.

## V13 — Scalar-output prediction shape bug in the tool (found by review 03, 2026-11-05)
For outputs with a single column, `GPFull.predict` and `PodGP.predict` returned 1-D arrays that broadcast against (n, 1) targets, giving meaningless NRMSE for full-field GP members on the real datasets (20-74). Fixed (predictions reshaped to (n, m)), regression test added. The real-data runs were re-checked with the fixed tool (`results/s6/real_recheck_after_shape_fix.json`; see the paper's real-data paragraph).

## V14 (2026-11-05, before any Stage 7 surrogate was fitted): `disc_elast` boundary-region bug found by unit tests
The first version of `make_disc_elast` selected the clamped and loaded arcs with `facets_satisfying` on a coordinate condition of facet midpoints; that picks interior facets inside the wedge as well, so a whole wedge was clamped and loaded, and the solution did not converge under mesh refinement (relative change between refinement levels about 0.5). The unit test for mesh convergence exposed it. Fix: select boundary facets only, by polar angle of the facet midpoint, and place the probes at 41 fixed physical points (not at mesh nodes of one particular level); mesh level raised from 4 to 5. A regression test asserts that the centre probe moves. Nothing had been fitted to this problem. Effect: none on earlier results (the problem is new).
