# Protocol addendum v3.0 (Stage 6) — pre-registered BEFORE any surrogate was fitted to the new problems
Written 2026-11-02 after the three review rounds of the v4 paper. Motivation: the reviewers' main remaining objections were (i) no problem solved by independent third-party code, (ii) lightly tuned networks, (iii) the paper offered no tool for the practitioner it is addressed to. Stage 6 addresses all three. All outcomes below are decided before the first model is fitted to the new problems; what was looked at beforehand: solver run times and value ranges of the new problems (to check they run and are finite) and 6 unit tests of the new solvers (series solution, scaling, mesh/time convergence). No error of any surrogate on these problems had been seen.

## 6.1 New problems (third-party solver: scikit-fem 12.0.2, `problems_tp.py`)
Eight instances, four families × two levels: `lshape_L1/L2` (plane-stress L-shaped plate; p = 4 / 7; stiffness regions + load angle; m = 130), `heatcomp_L1/L2` (composite conduction; p = 4 / 9; m = 256), `heatmove_L1/L2` (transient heat, moving Gaussian source; p = 3 / 5; m = 192), `convdiff_L1/L2` (steady convection–diffusion; p = 3 / 4; m = 256). Data protocol identical to earlier stages (4096 pool, 1000 test, 500 extrapolation, nested training subsets by seed permutation).

## 6.2 Experiments
* **T (legacy methods on the new problems)**: the five original methods, B = 8, 1500 epochs, N ∈ {64, 256, 1024}, seeds 0–2. **Prediction PT** (stated now): the reduced-basis family is clearly better (ȳ > 0.10, validation-selected) at N = 1024 on **at least 5 of the 8** new problems. Reported either way; this is the external check of the main empirical finding.
* **S (strong tuned network)**: `TunedMLP` (surroselect.nn): Optuna TPE + successive halving, 16 trials (8 for N = 64 omitted: S is run at N ∈ {256, 1024} only), full-batch float64, search over output type (full field or POD rank 8/16/32), depth 2–4, width 64–256 (restricted before any run for compute reasons; the default of the tool is the same), activation, lr, weight decay; validation split 20 % of the training runs; final retraining on all runs with 4× epochs (6,000 full-batch epochs) and 200 L-BFGS iterations; search trials train 1,500 full-batch epochs. Seeds 0–2, new problems only (48 jobs). The tuning budget is twice that of any other method.
* **C (SurroSelect evaluation)**: `SurrogateSelector` (default pool: POD+GP[matern52, r=32], POD+GP[rbf, r=32], POD+GP[matern52, r=8], POD+KRR-wide, POD+Poly, GP-full[matern52], GP-full[rbf]; 4-fold CV; tie band 0.1 decade; random_state = seed), N ∈ {64, 256, 1024}, seeds 0–2, same training subsets as T/S; `refit_all=True` so that the test error of every pool member is available (oracle); learning curve of the selected model computed from the training data only.

## 6.3 Pre-registered criteria (cells = instance × N; seed-mean test errors; 24 cells unless stated)
* **S1 (selection quality)**: median over cells of err(selected)/min over pool of err ≤ 1.5, **and** ≥ 75 % of cells ≤ 2.0.
* **S2 (not worse than fixed GP baseline)**: median over cells of err(selected)/err(legacy POD+GP of experiment T) ≤ 1.0.
* **S3 (vs the five legacy methods)**: let L = the legacy method with the smallest validation error in each (instance, N, seed) (the benchmark's own selection rule); median over cells of err(selected)/err(L) ≤ 1.0, **and** the number of cells in which the tool is better by > 10 % exceeds the number in which it is worse by > 10 %.
* **S4 (vs strong tuned network, N ∈ {256, 1024}, 16 cells)**: the strong network is better than the tool-selected model by more than 25 % in **at most 4 of 16** cells. No directional claim beyond this is made.
* **B1 (learning-curve error prediction)**: for N0 ∈ {64, 256}: central prediction of the selected model's test error at 4·N0 (extrapolated power law through the last three CV learning-curve points) versus the test error of the **same candidate** refit on 4·N0 runs (same seed): |log10(pred/actual)| ≤ log10 2 in **≥ 70 %** of the 48 (instance × N0 × seed) cases. Also reported: share in which actual lies within the (low, high) band.
* **B2 (reach-target classification)**: from N0 = 256, predicted (central) error at 1024 ≤ 1 % versus actual (same candidate, seed): accuracy ≥ 75 % over 24 cases (instance × seed); same for 0.1 %.
* **F1 (basis-limit flag)**: among cells where `basis_limited` is True, the best GP-full test error beats the best POD-based pool member by more than 10 % in ≥ 75 % of those cells (evaluable if ≥ 5 flagged cells; otherwise reported as not evaluable).
* **K (cost)**: wall-clock seconds of one `fit` + `learning_curve` at each N are reported; no criterion.

## 6.4 Secondary, design-informed (labelled as such)
The tool's candidate pool and the KRR/poly grids were designed with knowledge of the 36 earlier problems, so any evaluation on them is **in-sample** with respect to design. We therefore report a retrospective run of the tool on the 36 earlier problems at N = 256, seed 0 only, as a descriptive table, not as evidence for criteria S1–B2.

## 6.5 Rules
A failed fit counts as infinite error; no criterion, pool member, grid or data protocol is changed after the first result of the experiment concerned; any deviation is logged in `research_design/deviations_v2.md` (new entries V9+). Criteria are not tuned to the results. Whether criteria are met will be reported plainly, including failures. Positive results on 8 problems from 4 families (2 levels each) are descriptive of those families, not general.
